## 1. 产品定义

### 1.1 高级主机管理（`pro.hostManagement`）

1. **手动分组**：新建、重命名、删除、排序分组；每个分组有名称、颜色、图标。所有协议的主机（RDP、RustDesk、SSH、VNC、Moonlight、AI）都能加入分组，一台主机最多属于一个分组。
2. **智能分组（只读、按规则自动归类）**：最近使用、在线、离线、按协议、按标签、按网段（如 `192.168.31.0/24`）、未分组。规则是本地计算，不写回主机。
3. **标签**：主机可以有多个标签（如「生产」「客户 A」），标签可以用于搜索和智能分组。
4. **批量操作**（多选后底部操作栏）：
   - 移入分组 / 移出分组、添加 / 移除标签、上锁 / 解锁、删除（现有）；
   - 批量编辑非敏感字段：端口、用户名、RDP 分辨率/画质/网关、RustDesk 中继、SSH 代理配置和密钥引用、VNC 缩放/只读；只对选中协议适用的字段生效，其余自动跳过并提示；
   - 批量连通性检测：并发探测在线状态，结果写回现有 presence 状态；
   - 导出 / 导入：JSON（不含任何密码、私钥、令牌），导入时预览并检测重复。
5. **排序**：手动拖拽排序（写 `sortOrder`）、按名称、按最近使用、按在线状态。
6. **重复检测**：同协议、同地址、同端口、同用户名的主机给出合并或保留提示，不自动删除。

### 1.2 工作区与布局（`pro.workspaces`）

1. **工作区**是一组「会话条目」的有序集合，有名称、颜色和图标。每个条目指向一台主机，并可附带打开参数：
   - 通用：打开顺序、是否自动连接；
   - RDP：显示器、缩放、控制模式；SSH：初始窗格（终端/文件）和目录；RustDesk/VNC：缩放模式；
   - PC 布局：窗口矩形（相对屏幕比例）与是否全屏。
2. **一键打开**：按设备能力分三种形态打开：
   - PC：每个桌面类会话一个独立窗口，按保存的矩形摆放；SSH 条目合并进一个 SSH 工作台窗口，按顺序开标签；
   - 平板：前两个条目用系统分屏（左右），其余进入会话切换条；
   - 手机：依次在后台准备，前台显示第一个，顶部会话切换条可快速切换。
3. **从当前状态保存**：在已打开多个会话时，一键「保存为工作区」，自动采集当前会话、视图和窗口位置。
4. **布局编辑器**（PC/平板）：在缩略画布上拖动窗口矩形，提供「左右平分 / 三栏 / 主副 / 四宫格」预设。
5. **失败处理**：任一条目连接失败只影响该条目，工作区其他会话继续；汇总面板列出每个条目的结果和重试入口。
6. 工作区只保存引用和非敏感参数；凭据仍由各主机自己的保存策略提供，不在工作区中存密码。

### 1.3 Pro 边界与降级

- 两个功能都由 `ProEntries.visible('pro.workspaces' | 'pro.hostManagement')` 门控。
- **Pro 失效（退款撤销、切换账号、模拟免费）时**：数据保留不删除；分组/工作区入口隐藏；首页回到普通列表。已有主机的连接完全不受影响，核心连接永远免费。
- 手动分组的**只读展示**是否对免费用户开放，列为待决事项（见 §9）。默认方案：免费用户看不到分组 UI，但数据保留，重新开通后恢复。

## 2. 数据模型（后端 · 本地数据层）

### 2.1 存储方案对比

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 分组定义、标签、跨协议归属、工作区定义存为 `usersettings` 结构化行（`payload` + `schemaversion`）；远程主机的分组同时回写 `RemoteHost.groupId` 以兼容旧筛选 | 无需改云端表；已有冲突处理和账号作用域 | `usersettings` 在「管理同步数据」里显示为「跨设备外观设置」，需要把文案改成「跨设备外观、分组与工作区」 |
| B | 新建云端表 `hostorganization` / `workspaces` | 语义独立，可单独开关同步 | 需要在 AGC 部署新 schema（外部依赖），迁移和回滚成本高 |

采用方案 A。若之后需要单独开关同步，再以 B 作为后续迁移，不阻塞本期。

### 2.2 行定义（`usersettings.key` 前缀 `pro.org.` / `pro.ws.`）

```
pro.org.groups.v1        payload: { groups: [{ id, name, color, icon, order, createdAt, updatedAt }] }
pro.org.membership.v1    payload: { byHost: { "<hostRef>": { groupId, tags: [string] } }, updatedAt }
pro.ws.<workspaceId>     payload: { id, name, color, icon, order, entries: [WorkspaceEntry], layout: LayoutPreset?, updatedAt }
```

- `hostRef` 统一为跨协议引用：远程主机用 `host.id`，VNC 用 `vnc:<recordId>`，Moonlight/AI 用各自投影 ID（沿用接续功能已验证的 `resolveProContinuationHost` 解析规则）。
- `WorkspaceEntry`：`{ hostRef, protocol, order, autoConnect, view: { … 协议白名单字段 … }, frame?: { x, y, w, h, fullscreen } }`。`view` 复用接续信封 `ProConnectionView` 的白名单校验，不接受任何密钥或任意字段。
- 所有 payload 设上限：分组 ≤ 100、每组名称 ≤ 32 字、每台主机标签 ≤ 10、工作区 ≤ 30、每个工作区条目 ≤ 16；超限拒绝写入并提示。
- `schemaversion` 从 1 开始；解析失败或版本更高时只读保护，不覆盖云端。

### 2.4 一致性与安全规则

1. **账号隔离**：所有 store 通过 `AccountSessionCoordinator` 作用域绑定；切换账号时清空内存并重新加载，旧账号数据不得泄漏到新账号。
2. **冲突**：按行最后写入胜出（`updatedAt`），分组定义与归属拆成不同行，降低并发覆盖面；本机未同步的修改走现有 dirty/journal 机制。
3. **悬空引用**：主机被删除后，归属与工作区条目保留但标记「主机不存在」，在 UI 中可一键清理；不自动级联删除工作区。
4. **批量编辑不碰凭据**：密码、私钥、RDP 凭据、RustDesk 设备密码不在批量编辑白名单内；「SSH 密钥引用」只改引用 ID，不读取私钥。
5. **导出**：序列化只走白名单；测试断言导出结果不包含 `password/privateKey/passphrase/token/secret` 任何字段名或已知值。
6. **工作区打开**：每个条目都走该协议正常的预检、主机锁、应用锁和凭据流程；工作区不能绕过任何认证。
7. **权益**：写操作前检查 `ProEntries.visible`；Pro 失效后 store 只读、UI 隐藏；数据不删除。Release 构建中 `availability` 保持「敬请期待」直到 1.2.0。

## 3. 前端交互与视觉设计

设计语言沿用现有规范：大圆角卡片（22–24vp）、`BlurStyle.Regular` 半透明卡片、主题色 `accentColor`、Pro 标（流动幻彩）、手机/平板/PC 三断点、深浅色自适应。

### 3.1 首页主机列表

1. **分组胶囊栏**（替换现有纯文字筛选）：横向滚动胶囊，依次为「全部」「最近」「在线」+ 用户分组。每个胶囊带颜色圆点、名称和数量徽标；选中态为主题色描边加浅色底，切换带 200ms 缩放/淡入。末尾「＋」新建分组，长按胶囊进入「编辑分组」。
2. **分组视图（平板/PC 分组模式）**：每个分组一张分组卡片（沿用 `HostGroupCardPolicy` 的卡片样式），标题栏显示分组色条、名称、在线/总数，可折叠；卡片内主机按 `sortOrder` 排列，支持拖拽排序和跨组拖放。
3. **主机卡片**：右上角显示分组色点和最多 2 个标签小胶囊；超出显示「+N」。
4. **空状态**：分组为空时显示插画式空卡片和「从主机列表添加」按钮。

### 3.2 多选与批量操作

1. 长按主机或点「多选」进入选择态：卡片左侧出现圆形勾选，顶部显示「已选 N 台 · 全选 · 取消」。
2. 底部浮起操作栏（毛玻璃、圆角 24），图标加文字：移入分组、标签、批量编辑、检测连通、导出、上锁、删除。与当前协议不适用的动作置灰并说明原因。
3. **批量编辑弹窗**：分节展示可改字段；每个字段左侧有「修改」开关，打开后才生效；底部「预览变更」显示逐台 diff（旧值 → 新值），确认后执行，完成后给出成功/跳过/失败统计并支持撤销最近一次批量编辑（内存快照，退出页面后失效）。
4. **批量连通检测**：进度环 + 实时计数，结果以在线/离线色点回填卡片。

### 3.3 分组与标签管理弹窗（设置 → Pro 功能 → 高级主机管理，以及胶囊栏长按）

- 分组列表：拖拽排序、左滑删除（二次确认，说明主机不会被删除）、点按编辑名称/颜色（12 色调色板，与主题色协调）/图标（系统 symbol 精选 24 个）。
- 标签页：全部标签及使用次数，可重命名、合并、删除。
- 智能分组开关：选择在胶囊栏显示哪些智能分组。

### 3.4 工作区

1. **首页入口**：主机列表顶部新增「工作区」横向卡片带（Pro 可见），每张卡显示图标、名称、条目数、协议图标堆叠和「打开」按钮；最后一张为「＋ 新建」。
2. **工作区编辑器（全屏 sheet）**：
   - 顶部：名称、颜色、图标；
   - 条目列表：每条显示主机、协议、打开参数摘要；右侧拖柄排序；点按展开该协议的视图选项；
   - 「添加主机」从主机选择器多选加入；
   - PC/平板显示「布局」页签：缩略画布上以圆角矩形表示窗口，可拖动/缩放，顶部预设按钮（左右平分、三栏、主副、四宫格），吸附到 8 等分网格。
3. **打开过程**：底部浮层显示每个条目的进度（排队 → 连接中 → 已连接 / 失败），失败条目可单独重试或跳过；全部完成后浮层自动收起。
4. **会话切换条**（手机/平板）：打开工作区后在会话顶栏显示当前工作区名称和横向会话标签，点按切换、长按关闭单个会话。
5. **保存当前会话**：会话菜单中新增「保存为工作区」，弹出草稿编辑器，预填当前所有活动会话。

## 6. 设备验收清单（新增到全计划验收单）

- HM1 新建/重命名/删除/排序分组；六种协议主机都能加入分组；两台设备同账号同步一致。
- HM2 智能分组「最近/在线/离线/网段/未分组」结果正确。
- HM3 批量移组、标签、锁定、删除；批量编辑预览与撤销；凭据字段不可被批量修改。
- HM4 批量连通检测结果正确；导出文件不含任何密码/私钥；导入去重。
- HM5 Pro 撤销后入口隐藏、数据保留；重新开通后恢复。
- WS1 新建工作区（≥3 条目、混合协议）；编辑、排序、删除；两台设备同步。
- WS2 手机打开工作区：会话切换条、失败条目重试；平板分屏；PC 多窗口按布局摆放（PC 到位后）。
- WS3 从当前会话保存为工作区，参数与视图正确。
- WS4 工作区打开时每个条目仍要求应用锁/主机锁/凭据；不绕过认证。
- WS5 账号切换后看不到另一账号的工作区。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| `usersettings` 同步被用户关闭导致分组不跨设备 | 管理同步数据文案改为「跨设备外观、分组与工作区」，并在分组页提示当前同步状态 |
| 多会话同时连接占用内存/带宽，低端手机卡顿 | 手机端串行连接并限制同时活动会话数（默认 3）；超出时提示 |
| 平板系统分屏 API 能力差异 | 能力探测失败时回退为会话切换条 |
| PC 窗口矩形在不同分辨率下失真 | 存相对比例并在恢复时夹紧到可见区域 |
| 批量编辑误改大量主机 | 必须预览 diff、逐字段开关、可撤销最近一次 |
| 悬空引用（主机被删） | 标记并提供清理，不级联删除 |

## 10. 实现记录（2026-10-01）

在 Codex 的数据层（W0/H1/S1）之上补齐了界面和打开流程：

| 阶段 | 实现 | 与计划的差异 |
|---|---|---|
| H1 | `HostOrganizationStore` 增加改色/改图标、排序、批量移组、标签增删改并、失效记录清理、导入；写入先校验再落盘，失败不改内存。不再双写 `RemoteHost.groupId`（归属表是唯一来源，VNC/Moonlight/AI 也能分组） | 去掉双写，避免每次分组都触发主机行云同步 |
| H2 | 首页 `HostGroupBar`：全部 + 智能分组 + 用户分组胶囊（色点/图标/数量），长按或齿轮进入 `HostOrganizationManager`（分组、标签、智能分组、整理四页）；卡片显示分组色点和最多 2 个标签；分组/卡片模式都生效 | 分组排序用上下箭头而非拖拽 |
| H3 | 多选底部浮动操作栏 `HostBatchActions`：移入分组、标签、批量编辑（逐项开关 + 预览 + 撤销）、检测连通（4 并发）、导出、上锁/解锁、删除 | 批量编辑只开放不影响路由与凭据的字段：RDP 端口/分辨率/色深/多显示器、SSH 用户名/密钥引用；SSH 端口（涉及代理路由）、RustDesk 中继（涉及端点推导）、VNC 字段不开放 |
| H4 | JSON 导出（白名单，无密码/私钥/令牌）、导入预览：已存在主机一键应用分组与标签，新 RDP/SSH/VNC 主机打开预填的添加表单由用户填凭据；重复主机检测可「在列表中选中」 | 不直接创建主机（凭据必须走原表单校验） |
