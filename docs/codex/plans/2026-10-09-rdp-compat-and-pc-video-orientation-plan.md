# RDP 兼容性与鸿蒙 PC 视频方向（2026-10-09）

## 背景

- 用户反馈：mstsc 能连的电脑，我们报「目标 RDP 地址解析失败」或长时间停在「正在检查 RDP 证书」。
- 鸿蒙 PC 上 RustDesk 只要走硬件解码（Windows 被控端，H.264 / H.265）画面就上下颠倒；手机、平板正常。手动翻转只是兜底。没有 PC 实机，只能靠用户导出的诊断定位。

## 已查明

### RDP
1. 解析：原生 `getaddrinfo` 失败后用 NetworkKit 再查一次，都只走 DNS。mstsc 还会用 LLMNR、NetBIOS、mDNS 和 DHCP 下发的域名后缀，所以填电脑名（`DESKTOP-XXXX`、`xxx.local`）时只有我们失败。
2. 预检耗时：原生探测（解析+TCP 共 5 s、协商 8 s、TLS 8 s）之后，只要是域名就再解析一次并逐个地址重探，第一次成功也照做；解析与 TCP 共用 5 s，DNS 慢就被误报为解析失败。
3. 旧 TLS：FreeRDP 3 默认最低 TLS 1.2、安全等级 2；OpenSSL 3 默认等级下 TLS 1.0 服务器握手即被拒（本机实测 `alert protocol version`，等级 0 可握手）。Win7/2008 R2 未更新、部分设备只支持 TLS 1.0/1.1。FreeRDP 官方也要手动 `/tls:seclevel:0`。
4. 标准 RDP 安全层：FreeRDP 官方按 NLA→TLS→RDP 自动回退（`nego.c`）；我们只在用户「仍然继续」后允许。
5. NLA 只用 NTLM（无 Kerberos 缓存）；NTLM 被禁用或 NLA 失败时，只能改用不经 NLA 的 TLS 登录（服务器不强制 NLA 时）。

### RustDesk PC 方向
- 手机/平板：NativeImage 采样用单位矩阵，不读生产者矩阵。
- PC：读 `OH_NativeImage_GetTransformMatrixV2`，按「左上原点换算」（M·FlipY）采样；矩阵为 FlipY 时与手机等价。用户反馈 PC 硬解一律颠倒，说明真机上要么矩阵不是 FlipY，要么驱动的外部纹理原点约定不同；现有导出缺少能区分两者的事实。

## 实施

### R1 局域网电脑名解析（原生 + ArkTS）
- 新增原生 `LocalNameResolver`：mDNS（`.local` 或单段名追加 `.local`，224.0.0.251:5353，QU 位）、LLMNR（单段名，224.0.0.252:5355，A/AAAA）、NetBIOS 名称查询（单段名，UDP 137 广播，`<20>`/`<00>`），并行发出，总时限约 1.5 s，返回数字地址。
- ArkTS DNS 兜底：NetworkKit 失败或无结果时，先试连接属性里的域名后缀，再调本地解析。结果作为现有 transportHost 候选，证书仍按原名校验。
### R2 预检提速与阶段提示
- 原生探测成功、或失败原因与解析/TCP 无关时，不再枚举重探。
- 原生探测解析与 TCP 分开计时（解析 8 s，连接 5 s）。
- 证书面板显示当前阶段（连接并读取证书 / 查找局域网电脑 / 尝试第 i/N 个地址）。
### R3 旧 TLS 由用户决定
- 探测 TLS 失败且属于版本/算法不兼容时，自动用兼容参数（等级 0、最低 TLS 1.0）只读取证书（不发凭据），归为 `E-RDP-TARGET-TLS-LEGACY`。
- 证书面板说明风险并提供「仍用旧版 TLS 连接」；选择后本次连接 FreeRDP `TlsSecLevel=0`、`TLSMinVersion=TLS1.0`。可勾选「这台主机以后都允许」（本机保存）。
### R4 NLA / NTLM 失败由用户决定
- NLA 认证阶段失败（非密码错误类）时，在错误界面提供「改用 TLS 登录（不使用网络级身份验证）」，即现有 TLS 兼容登录，本次或以后都用；服务器强制 NLA 时说明无法降级。
- 标准 RDP 安全层的「仍然继续」文案改为白话说明风险。

### V1 视频方向诊断
- 渲染器：GL 厂商/渲染器/版本、EGL 版本。
- 解码器：组件名、是否硬件、输出格式（宽高、步长、slice 高、像素格式、裁剪、旋转）。
- NativeImage：V1 与 V2 矩阵、缓冲区变换。
- 码流：首个关键帧的 NAL/SEI 类型，显示方向 SEI（如有）解析出的翻转与旋转。
- 设备型号与系统版本进入导出清单（型号不是个人标识）。
### V2 方向自检
- 原生自检：用离线生成的四色（左上红、右上绿、左下蓝、右下白）H.264 / H.265 单帧，在独立 EGL pbuffer 上下文中用同一 mime 的硬件解码器解码到 NativeImage，按「单位矩阵」与「当前模式」各渲染一次到 FBO，读回四角，得出方向类别（正常 / 上下 / 左右 / 旋转 / 失败阶段）。
- PC RustDesk 首次硬解前在后台按编码各跑一次并缓存；手机/平板也可运行用于验证自检本身（真值已知：正常）。
- 结论进入日志、诊断导出和诊断浮层。
- 自检结论明确为轴对齐翻转时，PC 硬解采样自动叠加校正（只作用于 PC 桌面路径），手动翻转仍然叠加在最上层；首次自动校正时提示。

## 验证
- 原生：名称解析报文编解码、四角分类、矩阵合成单测；四项 Hvigor 门禁与测试登记；node 源码约定测试。
- 手机/平板实机：自检结论为正常；RDP 用电脑名连接。
- PC 无实机：自检与诊断字段在导出中可见，待用户反馈。
