# 远程 AI 原生插件：鸿蒙端开发交接

日期：2026-09-08。范围：电脑端无 Docker 插件与本机部署；准备 AI4 客户端开发。本文件不表示鸿蒙工作台、设备配对或双机 LAN 已实现。

## 已有电脑端合同

- Codex/DSH 均使用原生工具、原生沙箱、审批和结构化问题；不再使用 0.2.0 的三个容器工具。远端扩展和子 Agent 委派尚未开放。
- 传输已经确定为 HTTPS JSON RPC + SSE；不是原计划里的待定 WSS。协议主版本仍为 1，客户端必须握手读取具体 capabilities。
- 支持会话列表/创建/恢复、流式消息、历史分页、模型与推理设置、改名/分叉/压缩、受管理终端列表与停止、文本和图片附件、操作回执与控制器租约。
- 发布提交、安装包 SHA256、固定文档入口由[电脑端安装提示词](2026-09-07-remote-ai-agent-install.md)维护；实现参数以对应发行版 `docs/protocol.md` 和 `packages/protocol` 为准。早期 AI0 文件保留为历史证据。

## AI4 开始前先完成通信与信任验证

已核对本机 API 26 及保留的 API 23 声明；实际编译 SDK 以当次门禁和 CURRENT 记录为准。当前应用 target/compatible 仍为 API 23，应分别确认实际编译 SDK 与兼容目标；本次不修改它们。

`@ohos.net.http` 提供 `clientCert`、`caPath/caData`、`certificatePinning`、`requestInStream` 及分块接收事件；API 23 也包含这些接口。`ClientCert` 使用证书和私钥文件路径；不能直接宣称支持 HUKS 不可导出私钥参与 TLS。先用真实设备证明私有证书存储、CSR、客户端认证、清理和恢复，再确定 HUKS 包装或 native TLS 方案。

特别注意：API 26 声明说明 `caPath/caData` 会与系统预置 CA 一起使用，不能把设置自签 CA 等同于只信任该 CA。现有邀请提供私有 CA 与服务实例标识，尚未提供独立服务器 SPKI pin。第一项设备技术验证必须确定严格服务身份校验：验证可限定信任根的 native TLS，或经过协议扩展和可信邀请交付的服务器公钥 pin；禁止把 CA 公钥 hash 直接当成未经验证的服务器 pin，也禁止跳过主机名或证书校验。

最小设备闭环：导入可信邀请 → 在设备生成密钥和 CSR → 配对 → mTLS 握手 → 项目列表 → 新建会话 → 真实模型回复。另测错误 CA、错误 SAN、过期/撤销设备、重复邀请、App 重启、证书文件缺失，以及分块 UTF-8/SSE 边界。文件和密钥只进 App 私有区，不进入日志、云同步或通用连接导出。

## 客户端实现顺序

1. 建立独立连接配置和 RPC/SSE 传输层；按实例、设备和项目隔离本地数据。持久保存原始 operationId、epoch 和 payload；遇到 unknown/超时先查原回执，不自动改 ID 重发。
2. 实现设置 → 远程 AI 工作台 → 电脑端安装，提供两个版本固定提示词的预览/复制和操作手册入口。插件已安装、服务 ready、电脑模型可用、App 已配对分开显示。
3. 实现项目/会话列表和会话页，按后端 capabilities 展示模型、推理强度、权限模式和协作模式；不虚构自定义 provider 的完整模型目录。缺少元数据表示未知。
4. 接入审批与结构化问题。Codex 文件审批直接展示 `request.nativeItem` 的完整路径、增删改移动和 diff；断线后从 `approval.list` 恢复，不仅靠历史/旧事件。普通批准仅一次；权限扩大须展示范围和明确 turn scope。秘密输入留在宿主。
5. 补齐分页、重连和活动状态。DSH 原生流式 chunks 很快超过 200 条一页，必须读取 nextCursor；Codex turns/items 也分别分页。按稳定 ID 去重，正确应用 DSH surfaceOp replace；不能把旧最终回复或单个 turn/end 当成整个 Agent 已停止。
6. 完成改名、分叉、压缩、附件和受管理终端。压缩 accepted 仍需等待后续完成/失败事件；取消确认仅覆盖原生受管理活动。控制器每 30 秒续租，切换/断线后处理租约失效与待审批失效，不静默接管其他设备。
7. 接入已有 Pro 服务与 `pro.lifetime`，能力在设备验收通过前保持 planned；不改变普通 SSH 终端中使用 AI 的免费能力。手机、平板、PC 分别做布局和后台/前台切换验收。

## 后续验收与边界

电脑端本机参考客户端使用真实配置模型完成的结果由部署验收记录提供；固定模型 CI、真实宿主模型、真实手机连接属于不同证据。App 完成后另做双设备 LAN、网络中断/重连、撤权、跨设备单写者、进程重启及证书轮换。

RustDesk 为后续 AI6/AI7：只使用用户自建且授权的服务，经标准 PortForward 建立字节流，保留同样的端到端服务身份和设备认证。回环隧道不能因为地址是 localhost 就放松 TLS 校验。

继续同一应用活动分支，保留并行 Pro 修改。每项应用实现遵守当前 AGENTS 的 API 26/兼容检查、两项 Hvigor、适用测试、Light 和独立复核；不能以电脑端已就绪代替客户端验收。
