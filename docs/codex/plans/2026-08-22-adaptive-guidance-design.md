# 多设备自适应引导方案

## 目标

让新用户在不阅读长手册的情况下完成第一次安全连接；让已有用户能在 2 次选择内定位到
当前设备、当前协议的操作步骤；关键会话只提示一次，不遮挡持续操作。

## 官方依据

- HarmonyOS 通用设计强调多设备体验的“一致性 + 差异性”：任务结构保持一致，按屏幕、
  输入方式和场景提供差异化交互。
  <https://developer.huawei.com/consumer/cn/doc/design-guides/design-concepts-0000001795698445>
- HarmonyOS Popup 适合给指定组件提供短帮助；必须等待页面构建完成后显示，避免位置与形状错误。
  <https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/arkts-popup-overview>

官方没有覆盖远程桌面五协议的成套新手引导组件，因此应用采用分层组合，而不是复制一套
超长轮播。

## 三层结构

1. 首次启动：7 页以内，只讲协议选择、设备差异、安全核验、数据边界和第一台主机。
2. 设置中的操作引导中心：先选手机 / Pad / PC，再选开始 / RDP / RustDesk / SSH / VNC /
   Moonlight。“开始”只放通用任务，具体协议页直接置顶并展开该协议的准备课程；其余课程按需
   展开为 4 个步骤和 1 条注意事项。
3. 就地提示：协议选择页说明服务端前置要求；SSH 和 Moonlight 首次成功会话显示一次短提示。
   RDP、RustDesk、VNC 继续沿用现有触控板与 VNC 工具栏提示。

## 设备差异

| 设备 | 默认强调 | 不应强迫用户学习 |
|---|---|---|
| 手机 | 贴边入口、触控板、虚拟键盘、双指手势 | PC 独立窗口与复杂拖放 |
| Pad / 展开态折叠屏 | 触控与外接键鼠混用、分栏、多任务 | 仅手机竖屏的单手路径 |
| PC / 2in1 | 实体键鼠、独立会话窗口、拖放、全屏 | 移动端手势作为主入口 |

设备类型优先读取物理设备事实；只有无法识别设备时才用窗口断点兜底。PC 自由窗口缩窄后仍
保持 PC 指引，手机横屏不会被长期误判为 Pad。

## 内容覆盖

| 范围 | 必须覆盖的任务 |
|---|---|
| 通用 | 添加/连接、主机整理、密钥与 2FA、云同步/备份、错误码/日志/反馈 |
| RDP | Windows 前置、认证与证书、输入/组合键、显示调优、剪贴板/文件 |
| RustDesk | ID/中继/批准/2FA、工具栏与输入、编码/显示、剪贴板/文件 |
| SSH/SFTP | 服务与认证、指纹/代理、终端/语言/多会话、SFTP、三类隧道 |
| VNC | Server/TCP/Repeater mode12、TLS 信任、输入/只读、画质/剪贴板、Gateway |
| Moonlight | Sunshine/配对、目录/恢复、触控/键鼠/手柄、画面/音频/网络、数据边界 |

## 克制规则

- 启动引导不放完整操作步骤，不超过 7 页。
- 引导中心一次只显示一个设备路径和一个协议路径。
- 每个课程先显示一行摘要，详细内容默认折叠；每课固定 4 步，注意事项不超过一段。
- 就地提示只在会话已可操作、没有阻塞弹层时显示；同一进程每类提示最多一次。
- 安全提示只出现在信任、凭据、覆盖、删除和公网暴露等有真实风险的节点。
- 设置页仍是功能配置源，引导中心只解释入口和操作，不复制可变状态或代替错误提示。

## 验收

- 三类设备均能看到与物理设备相符的默认路径，并可手动切换查看其他设备。
- 五种协议均至少覆盖准备、连接、操控和恢复/排障；不支持的能力明确说明替代路径。
- 首次引导与设置快速教程共享内容源；引导中心内容由纯策略过滤并有测试覆盖。
- SSH/Moonlight 短提示不在认证、配对或其他阻塞弹层上重复出现。
- 手机小窗、Pad、PC 自由窗口均可滚动到所有课程，不因内容增长撑出系统 Sheet。
