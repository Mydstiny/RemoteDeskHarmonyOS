# 文件传输全面整改（RDP / RustDesk / SSH，2026-10-08）

## 背景

- 验收中用户反馈："RustDesk 文件传输没法读远端目录，文件也没法选择，整个文件系统彻底坏掉了"。
- 用户随后要求："整个文件传输系统（各个协议的不同文件传输系统）需要全面排查优化，要优化用户操控流程、用户操控 UI、底层文件交换链路"。

### RustDesk 读目录失败的根因：被控端问题

- 被控 Mac 上运行 RustDesk 1.4.9，所有文件操作都要经过连接管理器 CM 进程：读目录、接收上传、新建、删除、改名。
- RustDesk 用 `is_prelogin()` 判断是否还在登录前，依据是 `/dev/console` 的属主是不是 root。
- 这台 Mac 已登录、未锁屏，`/dev/console` 却归 root。RustDesk 因此一直不启动 CM，服务端日志里 15:06 之后再没有出现 "Start cm"。
- 结果：文件登录成功（authState=3），但 ReadDir 永远收不到回复，30 秒后 `file_transfer:TimedOut`。

### 我们这边的缺陷

- 读目录失败后只显示"请检查文件会话授权"，没有说明原因。
- 远端目录读不出来时，「选择文件 / 选择文件夹」整个被禁用，发送流程卡死。

### 审计方式

4 个只读审计代理（Opus 5.5）分别审计以下四块，共报告约 200 条问题：
- RustDesk；
- RDP；
- SSH/SFTP；
- 公共任务、副本、多会话模块。

高危结论已抽查属实：
- `cleanupExpiredTransferArtifacts` 没有调用方；
- `CB_CAN_LOCK_CLIPDATA` 被注释掉；
- RustDesk 列目录和下载循环不回应 test_delay；
- SSH 任务上限为 64。

## 用户决定（2026-10-08）

1. RDP 和 RustDesk 改成与 SSH 相同的「本机 | 远端」双栏管理器，任务列表放在底部，去掉"先选发送/接收方向"这一步。
2. 从远端接收的文件，接收完成后每批弹一次系统保存框，不再先进 App 内的"本机副本"再手动另存。
3. RDP 发送由用户选择方式：
   - 剪贴板：自动 Ctrl+V，落到远端当前键盘焦点所在窗口；
   - 共享文件夹：放进 `\\tsclient\盘名`，远端自己取。
4. 用并行审计代理排查（已完成）。
5. 执行顺序：批 1 → 批 2 → 批 3 → 批 4 → 批 5，公共层先行。
6. 手机/平板的「本机」栏显示待发送清单，来源有：选择文件、选择文件夹、剪贴板、拖入。不展示传输箱等 App 内部目录。
   - 平板实测拒绝持久授权文件夹，PC 可以持久授权一个文件夹来浏览。
7. RDP 共享文件夹用完即清：
   - 远端写过来的文件：保存到本机后删除；未保存的 7 天后清理。
   - 本机放进去给远端的文件：会话结束时删除。
8. PC 自动接收远端复制的文件：小于 50 MB 的自动接收；更大的只列在「远端已复制的文件」里，由用户决定是否接收。

平台核对：`SystemCapability.FileManagement.UserFileService.FolderSelection` 在 phone、tablet、2in1 的 device-define 里都有。所以三类设备都能用 `DocumentViewPicker` 选择目标文件夹，目录接收不需要打包 zip。

## 分批

每批流程：提交 → 四项 Hvigor 门禁 → Light 合规门禁 → `git diff --check` → 独立复审 → 保留数据装到平板（装机前告诉用户） → 待验收清单新增 P 节。

### 批 1 公共层止血（不改界面结构）

**副本存储**
- 启动时和打开面板时在后台执行 TTL 清理，`cleanupExpiredTransferArtifacts` 目前是死代码。
- holder / publication 写入进程 epoch。重启后旧 epoch 的 holder 视为失效：
  - `clipboard` 批次直接删除；
  - 已完成的 `received` 批次转为"待保存"；
  - native 残片在确认没有句柄后删除。
- `rdp-shared` 纳入清理。

**任务记录**
- 新增可淘汰的终态 `handedOff`（RDP 已交给远端）和 `interrupted`（进程被杀）。
- 提供"清除已完成"和按时间淘汰。schema 升到 v2，并兼容读取 v1。
- 多文件任务的 commit 改为按文件计数，不再一次进入 `committing` 后锁死。
- 进入 commit 后不再响应取消。本地 import 只检查进程是否存活，不检查会话 lease。

**另存 / 导出**
- 与会话 lease 解绑，只看用户是否取消。
- 失败时删除自己创建的目标文件。
- picker 返回的单文件视为已授权覆盖。

**配额**
- 按实际增量预留，使用增量计数器，不再每次 reserve 都同步遍历整棵树。
- 空间不足、配额已满要给出看得懂的文案。

**队列与持久化**
- 队列按会话分开，本地导出不占网络槽。
- 新增 `queued` 状态，文案为"等待其他传输"。
- 进度只放内存；只在阶段变化或每 5 秒持久化一次。

**多窗口**
- 实况窗点击后带上 `sessionWindowId`，回到对应窗口。
- 后台保活服务改为按窗口持有。
- 空闲超时只在前台或已获得保活时累计。

**错误文案**：统一建立错误码 → 中文文案表（含建议操作），替换任务列表和各处原始诊断码。

### 批 2 RustDesk 文件链路重做（Rust + NAPI）

**会话级长驻 FileSession**，按 `(sessionId, nativeGeneration)` 建立：
- 只登录、认证一次；
- 一个读线程按 FileResponse 的 id 分发；
- 回应 test_delay，客户端每 5 秒主动发一次心跳；
- 空闲 5–10 分钟后关闭。

现状是每个操作新建一条连接，造成以下问题：
- 每次点击都要等几秒；
- 被控端每次都弹一次 CM；
- 请求批准模式下每个操作都要批准一次；
- 上传一个目录要 2N+M 条连接。

**被控端文件服务早判**
- 把登录后服务端主动推送的初始目录用作首屏，同时作为 CM 存活探测。
- 若心跳正常，但 8–10 秒内既没有目录也没有错误，返回 `peer_file_service_unavailable`。
- 透出 peer 的 platform 和 username，用于按平台给建议（macOS / Windows / Linux）。

**结构化错误**：TransferJob 记录阶段（路由 / 认证 / 操作）、错误类别和截断后的服务端原文。例如：
- `No permission of file transfer`
- `one-way-file-transfer-tip`
- macOS 隐私权限拒绝
- 目录不存在

**补齐操作**
- 删除文件、删除目录（含递归）、重命名、AllFiles 递归列目录、ReadEmptyDirs；
- 隐藏文件开关；
- 显示链接项；
- 目录批量上传、下载；
- 支持超过 2 GiB 的文件。

**正确性修复**
- 覆盖上传也必须等到 SendConfirm 或 digest。现在静默 1.5 秒就开始发送，CM 不在时会报假成功。
- 根目录拆分保留 `/` 和 `C:\`。
- 列目录回复要校验路径。
- 认证等待不计入空闲计时。
- 回收已结束但未 release 的 job。

**只读降级**：被控端是 macOS/Linux 时，AllFiles 和 Send 不经过 CM。所以 CM 不在时仍可按路径列出文件并下载，界面要说明受限原因。

**暂不做**：续传（协议支持 `transferred_size` / `offset_blk`，放到后续）。

### 批 3 RDP 文件链路

**剪贴板发送**
- 流保护：开启 `CB_CAN_LOCK_CLIPDATA`；或者远端仍在读取时推迟本机文字发布、保留旧流。现在本机任何一次复制，或第二次发送，都会打断远端正在粘贴的大文件。
- 进度：按 listIndex 累计 FILECONTENTS_RANGE 的读取量，判定"远端已读完"。
- 窗口不活动时跳过了自动粘贴，要明确提示用户。

**剪贴板接收**
- 改为多选后一次接收。
- 每次接收前重新请求清单，并显示有效期。
- 块大小改为 1–4 MB，流水线并发。
- 超时改为按空闲时间计。
- 失败时保留已完整提交的文件。

**共享文件夹**
- 远端栏直接列出共享目录的实际内容，observer 只叠加"正在写入"状态。
- 不确定性只记在单个文件上。
- 解析 DesiredAccess / CreateDisposition / CreateOptions，区分写入、读取和目录；删除时同步移除对应记录。
- 挂载失败可重试，各阶段给出文案。
- 增加清理和保留策略。

**新功能：通过共享文件夹发送**
- 先写隐藏临时名，写完再改名。
- 同名文件自动重命名。
- 发送后提示"在远端 此电脑 → 盘名 查看，可按 F5 刷新"（drive 通道没有实现目录变更通知）。

**能力拆分**
- 分为 `fileUploadClipboard`、`fileUploadShare` 和对应的下载能力。
- 远端禁止剪贴板传文件时，提示改用共享文件夹。

**PC 自动接收**：只自动接收小于阈值的内容，其余列在远端栏里由用户决定。

### 批 4 统一双栏管理器 UI（RDP + RustDesk）

**共用组件**（从 SSH 现有实现抽取）：
- `FileManagerDualPane`：手机用「本机 / 远端」分页；平板和 PC 宽度 ≥720vp 时左右并排。拖放挂在组件本身。
- `FileListView`：
  - 文件、目录、链接图标，显示大小和修改时间；
  - 多选（PC 用 Ctrl/Shift，手机长按）；
  - 右键 / 长按菜单；
  - 双击或 Enter 进入目录；Delete / F2 快捷键；
  - 用 List + LazyForEach 渲染。
- `PathBreadcrumb`、`TransferTaskPanel`（底部可折叠，按批次聚合）、`ConflictDialog`（跳过 / 覆盖 / 保留两份，加"应用到全部"）。

**RustDesk**：远端栏支持完整浏览和管理。本机文件随时可选；远端目标还没就绪时，先进入"待发送"并说明原因。

**RDP**
- 远端栏分两组："远端已复制的文件"和"共享文件夹 \\tsclient\盘名"。
- 发送时选择"粘贴到远端当前窗口"或"放入共享文件夹"。

**接收后保存**
- 每批完成后弹一次保存框：
  - 纯文件用 `save({ newFileNames })`；
  - 含目录用选择文件夹，再多根导出。
- 窗口不活动或 App 在后台时挂起，回到前台再弹；后台完成时发通知"点按保存"。
- 用户取消保存时，内容进入"待保存"，在 App 级入口可见，7 天后清理。

**移除的用户概念**：本机副本、恢复旧版副本（改为一次性静默迁移）、归属待核实、剪贴板正在提供、受控暂存区、RDPDR 等。

**VNC / Moonlight**：入口置灰，点击后说明协议不支持文件传输。如果存在同地址的 SSH 主机，提供「用 SFTP 打开」。

**外观**：沿用现有的圆角卡片和主题色，不做整体换样式（2026-09-19 的约束）。

### 批 5 SSH/SFTP 稳定性，并接入共用组件

- **统一执行路径**：页面单文件路径和旧批次执行器都改走 `SshSftpTaskEngine`。
- **引擎事件**
  - 引擎发出节流后的进度事件，开始时即可取消；
  - 冲突目标是目录或链接时让任务失败，不再静默卡住；
  - 重试会重排所有 failed / cancelled；
  - 失败后默认继续，最后汇总成功和失败数。
- **任务存储**
  - 批次存一条父记录，不受 64 条上限约束；
  - 终态按 LRU 淘汰；
  - 不再淘汰未开始的任务。
- **原生层**
  - 每个文件只开一个句柄；
  - 检查点改用 fstat，并降频；
  - 块大小改为 256 KB–1 MB；
  - 服务器缺少 fsync / posix-rename 扩展时降级；
  - 区分权限不足、空间不足、路径不存在等错误码；
  - 放开 512 MB 上限。
- **清理与目录处理**
  - 远端和本机的 partial 文件在终态时清理；
  - 拖放暂存改到沙箱；
  - 符号链接默认跳过并计数；
  - 能进入指向目录的链接。
- **交互**
  - 新建和重命名用弹窗；
  - 支持递归删除；
  - 取消全局 `sftpBusy` 锁；
  - 批次完成后刷新列表；
  - 显示"第 n/N 个"和总进度；
  - 重试时复用已授权的 URI；
  - 切换标签不中断传输；
  - 修复 PC 拖放；
  - 文案白话化，去掉 114 处 `[SFTP-XXX]` 前缀和 `ret=`。
- **接入共用组件**：底部任务面板和三协议共用任务模型；手机改为分页双栏；下载后弹保存框。

## 验证

- 每批跑四项 Hvigor 门禁、Light 合规门禁和 `git diff --check`。
- 涉及 Rust 时，运行 `cargo test`，并用 `scripts/build_rustdesk_ffi_ohos.sh` 重新生成 so。
- 纯函数与策略的 node 测试沿用现有 `scripts/tests/*.cjs` 写法；新增测试登记到 List。
- 涉及用户数据的部分（多根导出、覆盖、清理残缺文件、epoch reconcile）补 ohosTest 用例，只编译，绝不在设备上运行。
- 真机验收在平板和 PC 上做，被控端覆盖 Windows 和 macOS。macOS 被控端要先确认 `/dev/console` 归登录用户。

## 风险

- 重做 RustDesk FileSession 会改动 rendezvous、登录和认证的复用方式。需要保证不影响画面会话本身，文件会话仍走独立连接。
- RDP 开启剪贴板锁会改变 FreeRDP 的 cliprdr 行为，需要与 Windows 资源管理器实测。
- 迁移任务和副本的 schema 时不能丢失用户已接收但未保存的文件。
- `SshTerminal.ets` 约 2 万行，要分步拆：先抽纯函数和服务，再抽组件，最后删除旧路径。
