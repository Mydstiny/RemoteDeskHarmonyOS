# M7：可信购买、恢复、撤销和离线权益

继续当前活动分支。生产仍关闭，配置与实际联调完成后才满足启用条件。

## 实现次序

1. 可信服务端协议：华为账号服务器验证用户级 Access Token 与 OAuth Client ID；IAP ES256、固定根证书、完整证书链/CRL、专用 OID；查询最新订单及白名单校验。
2. 台账：先建立随机购买意图并绑定验证后的账号，作为 developerPayload 传入购买；新订单只通过这个服务端绑定认领。已有订单只恢复到原账号；不能通过客户端 owner 或复制订单载荷转赠权益。
3. 发货：订单与永久权益在一个持久事务里落盘，然后签发当前账号权益，最后确认发货。网络超时保留待处理任务，重试先查最新状态，唯一订单/token 保证幂等。
4. 恢复与撤销：完整遍历当前权益及未完成订单；签名通知只触发最新查询，定期主动对账；退款只撤销对应订单，不能误伤其他有效购买或免费连接。
5. App：配置固定 HTTPS 后端和权益签名公钥；服务端签名缓存按账号/环境隔离，验证失败不发货，短暂离线不当退款。缓存新鲜度与买断永久属性分开；撤销墓碑、版本及单调时间边界防止旧缓存重放。
6. 正式验收：后端实际部署、正式商品及商户配置、沙箱/真实购买恢复退款、断网、跨账号、多窗口及适用设备矩阵通过后才启用购买。

## 首个服务端增量

`server/pro-entitlement` 先实现第 1 项：实际 OpenSSL 路径与 CRL 检查、ES256 签名、固定华为 HTTPS 请求、账号身份派生、最新订单和通知验证。主机测试使用临时生成的 CA/CRL 做真实密码学验收；mock 仅用于华为网络响应，不冒充真实验单或沙箱成功。

订单数据按当前官方模型使用 productType 字符串 `1`、environment `NORMAL`/`SANDBOX`、purchaseTime/finishStatus/needFinish/revocationTime；不使用旧 HMS Android 的 RSA 订单协议。证据与可信根哈希详见服务端 PROVENANCE。

用户已授权直接检查和完善 AGC 收费准备与沙盒。当前项目已有非消耗型草稿 `RemoteDesktop_Pro_Test`（CNY 28.88）、Pro IAP 密钥；用户指定的实机帐号已成功加入沙盒名单。云函数已开通，尚未创建函数；页面列出 Node.js 20.x/latest，AGC 云托管为静态网站托管。部署前继续核对云数据库事务和运行时兼容性，不把函数临时目录作为永久台账。正式商户激活、通知回调、部署域名和实机购买/退款尚未完成。配置凭据不写入仓库或日志。

## 台账增量

`ab3a60ac + bbc7fb53` 实现 SQLite 持久订单/账号/意图事务、AES-GCM 订单 token 存储、发货 outbox 和签名权益。一次性权益永久保存，签名离线缓存默认每日重验、七天可用；网络失败不产生新的缓存有效期。该离线窗口是当前实现策略，后续可通过服务端版本化调整。

后台用独立持久扫描时间和退避公平处理失败订单；已终结退款只保留绑定与墓碑，不阻挡其他有效购买；状态与修订号使用同一数据库读快照。17 项台账回归和独立复核 PASS，包含真实 SQLite 故障注入与双连接竞争。华为协议模块另有 13 项检查与独立 PASS。当前结论仅覆盖代码与主机验证，HTTP/App 和实际沙盒闭环仍在推进。

服务端运行时 SBOM 独立记录，HAP 不增加 native 库或依赖。
