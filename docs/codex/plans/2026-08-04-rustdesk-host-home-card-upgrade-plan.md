# RustDesk 主页主机分组卡片升级计划

Status: 已实施，待完成项目门禁与集中审查。

Date: 2026-08-04

Design baseline: 当前线程中的 `rustdesk-host-groups.html` UI Demo，以及 Pad/PC
小屏的 v2 预览图。Demo 只作为交互和几何基线，最终实现仍须以 API 23、现有
ArkUI 组件和真实设备验收为准。

## 1. 目标

把远程主机主页升级为“按主机类型分组”的可选视图，同时保留现有未分组主页
作为兼容路径。在手机、Pad 和 PC 小屏开启个性化开关后，主页只展示四个固定
类型卡片：

1. Windows RDP
2. RustDesk
3. SSH 终端
4. VNC

Pad 和 PC 小屏采用 Demo 中的四张等尺寸大卡片；手机使用设置页风格的单列卡片。
点击某个类型后，类型卡片本身留在原来的网格位置，详情只插入该卡片所在行的
下方，并占满主页内容宽度。PC 大屏保持现有侧栏协议分类和列表，不受此开关的
主页卡片改造影响。
RDP、RustDesk、SSH、VNC 的详情和主机小卡片使用同一套视觉和交互合同。

RustDesk 类型需要在主机小卡片上显示 RustDesk ID，并显示可解释的在线、最近
在线、离线或未知状态；不能把中继服务器健康状态误当成被控主机在线状态。

## 2. 范围与边界

### 2.1 本计划包含

- 个性化设置中的“按主机类型分组”开关。
- 主页四类型分组投影、数量摘要和展开状态管理。
- 手机、Pad、PC 小屏的响应式布局合同，以及 PC 大屏原样回归合同。
- 统一的类型详情面板和统一的主机小卡片。
- RustDesk ID 展示、状态来源分类和刷新策略。
- 分组视图下禁用左滑编辑，改用卡片内显式编辑按钮。
- 现有连接、编辑、锁定和删除 owner 的调用边界与验收方案。

### 2.2 本计划不包含

- RustDesk 控制面、加密、认证、连接协议、视频或输入链路改造。
- RDP、SSH、VNC 或 RustDesk 的存储表合并。
- 把 RustDesk 中继配置记录投影成 RustDesk 被控主机。
- 在主页卡片中展示密码、token、服务器公钥、私钥或其他敏感凭据。
- 在没有真实 endpoint 合同的情况下，通过 TCP 超时推断 RustDesk 离线。

## 3. 不可变的体验合同

### 3.1 四张类型卡

- 分组视图始终按 RDP、RustDesk、SSH、VNC 的固定顺序展示四张卡。
- 没有主机的类型也保留卡片，数量显示为 0，并在展开后显示空状态。
- Pad、PC 小屏使用两列等宽网格；四张卡高度完全一致。
- Pad/PC 小屏基准高度为 220vp，宽度由内容区域两列等分得到；两列之间
  保留统一间距。最终数值以现有设计 token 和 API 23 设备密度校准。
- PC 大屏不进入分组卡片视图，继续使用现有左侧协议分类和主机列表。
- 收起状态沿用设置页收起卡片的层级、圆角、边框、图标容器和间距，不再使用
  现在的长条主机列表样式。
- 选中卡片只增加选中边框和向上箭头，不改变该卡片的高度、宽度或网格位置。

### 3.2 展开规则

- 同一主页同时只展开一个类型；点击另一个类型时，旧详情关闭，新详情插入
  新类型所在行的下方。
- 展开内容插入当前行之后，而不是插入当前卡片的网格单元，也不能导致同一行
  的其他类型卡片向下位移。
- 详情面板跨满主页内容区域宽度；Pad/PC 小屏不以当前半列宽度渲染详情。
- 第一行的类型在第一行之后展开，第二行的类型在第二行之后展开；手机单列时
  详情直接位于当前类型卡片下方。
- 页面刷新、状态刷新和窗口尺寸变化后，保留选中的类型 key，并按新的行布局
  重新计算详情插入位置。一次点击造成的展开不能触发额外网格重排。
- 分组视图下禁用左滑编辑和左滑删除；编辑、锁定、删除等操作只能从主机小卡片
  的显式按钮或现有编辑入口触发。

### 3.3 统一详情面板

所有协议使用相同的结构，不为 RustDesk 单独设计一套长条详情：

1. 面板头部：协议图标、协议名称、主机总数、状态摘要、刷新按钮。
2. 主机网格：Pad/PC 为两列，手机为一列；每张主机小卡片尺寸和间距统一。
3. 主机信息：名称、协议辅助信息、主标识、在线状态、最近检查时间或延迟。
4. 操作区：统一的连接主按钮和编辑按钮；锁定状态沿用现有 owner 规则。

RustDesk 主标识显示为 ID；RDP、SSH、VNC 显示各自的地址或端点。标识行
必须保持单行可读，过长值采用截断加可访问完整文本，不改变卡片高度。

## 4. 布局矩阵

| 设备/窗口 | 收起布局 | 展开位置 | 主机小卡片 | 关键验收 |
| --- | --- | --- | --- | --- |
| 手机窄屏 | 单列，设置页风格卡片 | 当前卡片正下方，100% 内容宽度 | 单列 | 无横向滚动；详情不遮挡下一类型 |
| Pad | 两列，四张 220vp 等高大卡片 | 当前行下方，跨两列 | 两列 | 展开后原四张类型卡不位移；详情跨满两列 |
| PC 小屏/2in1 | 两列，沿用 Pad 的尺寸合同 | 当前行下方，跨两列 | 两列 | 无横向溢出；点击第二行也只在第二行下展开 |
| 宽 PC | 保持现有左侧协议分类和列表 | 不进入本视图 | 保持现有主机列表 | 开关打开/关闭均不改变大屏主页结构 |

窗口从两列变成单列时允许发生正常响应式重排；在同一窗口尺寸内点击展开，
不得发生由详情插入导致的类型卡重排。

## 5. 数据投影和 owner 边界

主页只消费统一的只读投影，不建立新的“全协议主机表”。建议的投影字段如下：

| 投影字段 | 含义 | 规则 |
| --- | --- | --- |
| `groupType` | `rdp`、`rustdesk`、`ssh`、`vnc` | 由 owner 类型决定，不由显示名称猜测 |
| `hostKey` | 主机稳定标识 | 必须可跨刷新保持，不能用数组下标 |
| `displayName` | 用户可见名称 | 复用现有主机名称和空名称回退规则 |
| `identifierKind` | `rustdesk_id` 或 `endpoint` | 决定主标识标签和格式化方式 |
| `identifierValue` | ID、地址或端点 | 只读投影；不包含密码、token 或密钥 |
| `presenceState` | `online`、`recently_online`、`offline`、`unknown`、`checking` | 由状态 provider 产生，UI 不自行推断 |
| `lastSeenAt` | 最近一次可信状态时间 | 没有可信时间时显示未知，不伪造时间 |
| `latencyMs` | 最近一次有效检查延迟 | 不可用时隐藏，不显示 0ms |
| `capabilities` | 连接、编辑、锁定等能力 | 由原 owner 授权和锁定状态决定 |
| `sourceOwner` | RDP/RustDesk/SSH/VNC 来源 | 用于路由回既有编辑和连接入口 |

推荐的 owner 投影边界：

- `HostListPage.ets` 负责主页布局、分组开关读取、展开 key 和行插入规则。
- `HostCard.ets` 负责沿用现有主机小卡片信息层级和显式操作按钮；类型卡与
  主机小卡片的视觉 token 应从同一套组件合同派生。
- `RemoteHost.ets`、`HostSyncService.ets` 和现有 `HostListFilterService` 只
  提供 RDP/SSH 等已有记录的只读投影，不接受 RustDesk 专属字段的强行写入。
- RustDesk 普通主机、Pro peer、relay 和账号继续由各自现有模型与 service
  owner 管理；中继健康只作为连接辅助信息，不能覆盖 peer presence。
- VNC 继续使用 `VncHostService`、`VncRecord` 和既有 VNC owner；SSH 继续使用
  SSH/SFTP owner。主页只能消费它们的公开摘要。
- 个性化开关存入现有用户设置 owner，默认关闭；不写入主机云同步 payload，
  不要求迁移现有主机记录。

## 6. RustDesk ID 与在线状态方案

### 6.1 ID 展示

- 以主机 owner 保存或由其同步得到的 peer ID 为唯一来源，不从地址、名称或
  中继配置推算 ID。
- 数字型 ID 按官方可读分组格式展示；内部比较和连接仍使用原始规范值。
- 缺少 ID 时显示“ID 未获取”，保留连接/编辑能力所允许的操作，不显示假 ID。
- ID 行不展示访问 token、密码、设备身份密钥或服务器公钥；日志也不得打印
  这些字段。
- “复制 ID”可作为后续 P1 小增强，但不属于本次布局验收门槛；不能因此增加
  卡片高度或改变主操作位置。

### 6.2 状态语义

主页状态必须区分被控端 presence、连接检查结果和中继健康：

- `online`：由 RustDesk ID server/control-plane 或已约定的 peer presence
  接口在有效 TTL 内明确返回在线。
- `recently_online`：有可信 `lastSeenAt`，但已超过在线 TTL；展示“最近在线
  X 分钟”，不把它标成当前在线。
- `offline`：权威 presence 明确报告离线，或一次有明确协议意义的检查确认
  不可达。普通网络超时不能单独升级成离线。
- `unknown`：没有可用 presence 能力、没有可信历史、权限不足或检查未完成。
- `checking`：刷新期间的短暂状态；不计入在线数量，避免卡片摘要闪烁。

推荐默认参数：presence 缓存 TTL 60 秒；最近在线窗口 15 分钟；主页加载先
读取缓存，用户主动刷新时再发起检查。检查应有并发上限、超时和取消能力，不得
因为主页打开而为所有协议启动连接会话。若当前 RustDesk endpoint 只支持中继
健康，不提供 peer presence，则状态必须显示为“未知”，而不是复用中继的在线点。

类型卡摘要使用统一格式，例如“2 台在线 · 1 台最近在线 · 1 台未知”；主机卡
显示状态文字和最后检查时间，颜色只作为辅助，不作为唯一语义。

### 6.3 其他协议状态

RDP、SSH、VNC 沿用各自既有轻量状态或最近连接结果，接入同一个
`presenceState` 映射。主页统一显示，不要求本轮为三种协议新增深度探测。
任何协议的探测失败都只更新该主机的状态，不得阻塞四种类型卡片或其他协议的
连接入口。

## 7. 交互细节

### 7.1 类型卡

- 点击卡片主体或右侧箭头切换展开/收起。
- 卡片选中态只使用现有主色边框和箭头方向，不使用位移、放大或高度变化。
- 卡片摘要显示“总数 + 在线/最近在线/未知”三类数量；状态加载时保留原有
  数字并在右侧显示刷新中的轻量状态。
- 空类型卡可展开，详情中显示空状态和现有新增入口；空卡尺寸不能缩短。

### 7.2 主机小卡片

- 复用 RustDesk 中继 Pad 模式的连接主按钮视觉和尺寸合同；按钮语义是连接
  当前主机，不是编辑中继配置。
- 所有协议均使用同一位置的连接按钮和编辑按钮；协议差异只体现在连接路由
  和主标识字段。
- 连接按钮在能力不足、主机锁定或状态检查中时，遵循既有 owner 的禁用和
  提示语义，不由主页重新定义认证流程。
- 编辑按钮打开现有协议编辑入口；分组视图不恢复左滑编辑作为隐式后门。

### 7.3 刷新、返回和状态保持

- 详情头部刷新只刷新已展开类型，主页级刷新刷新四类摘要并保留展开 key。
- 连接返回主页后，保留用户最后展开的类型，并刷新该类型的缓存摘要。
- 切换关闭“按主机类型分组”后，回到现有未分组列表；不删除数据、不重排
  主机、不修改锁定和排序设置。
- 开关重新打开时默认保持上次展开类型；若该类型已不存在则回到第一类。

## 8. 预期实现阶段

### P0：设计和 owner 合同冻结

交付物：本计划、Pad/PC 小屏 Demo、四协议详情字段表、状态语义表。

完成条件：产品确认四张卡固定顺序、220vp 基准高度、两列布局、行下全宽
展开、分组视图关闭左滑编辑，以及 RustDesk ID 缺失/未知状态文案。

### P1：分组投影和个性化开关

交付物：只读的四协议分组投影、默认关闭的本地开关、空类型卡和兼容回退。

约束：不添加主机数据表，不把 RustDesk/VNC/SSH 记录迁移进 RDP owner；先只
验证数量、名称和编辑/连接路由，状态可以暂时为未知。

### P2：布局与统一详情面板

交付物：两列等高类型卡、按行插入的全宽详情、统一主机小卡片、显式编辑。

重点验证：第一行和第二行展开都不移动原类型卡；切换展开不会出现半列详情、
长条主机行或卡片高度漂移；手机单列不横向溢出。

### P3：RustDesk ID 与 presence adapter

交付物：ID 只读展示、权威 presence 接入、缓存/TTL/刷新/未知回退、状态摘要。

前置条件：先确认当前 RustDesk OSS/Pro endpoint 能提供的 peer presence 合同、
认证要求、错误码和限流策略。若 endpoint 只提供 relay health，则以未知状态
交付，不新增猜测逻辑。

### P4：四协议设备验收与灰度

交付物：Phone/Pad/PC 小屏验收记录、宽 PC 原样回归记录、灰度开关和回滚记录。

重点覆盖：空组、单主机、多主机、ID 缺失、最近在线、超时、锁定、编辑、连接
返回、窗口缩放、旋转和页面复用。

## 10. 验收矩阵

### 10.1 几何和交互

- 四种类型始终存在、顺序稳定、数量为 0 时仍等高。
- Pad 1024 宽和 PC 小屏基准宽度下，四张类型卡宽高一致，展开面板占满内容
  宽度且无横向溢出。
- 点击第一行 RustDesk，RDP/RustDesk 卡片位置不变，详情出现在第一行之后。
- 点击第二行 SSH 或 VNC，第一行保持原位，详情只出现在第二行之后。
- 切换 RustDesk、SSH、VNC、RDP，详情头部、主机小卡片和操作按钮保持统一
  风格，不出现协议专属长条布局。
- 手机单列、Pad 双列、PC 小屏双列和窗口尺寸变化均无遮挡、截断或错误焦点；
  宽 PC 保持既有侧栏分类和列表。

### 10.2 数据和状态

- RustDesk 主机显示真实 ID；缺失 ID 显示明确的未获取状态。
- relay health、API 可达和 peer online 三种状态可区分；中继在线不能直接
  让所有 RustDesk 主机显示在线。
- `online`、`recently_online`、`offline`、`unknown`、`checking` 映射和摘要
  数量一致；网络超时不会无条件显示离线。
- RDP/SSH/VNC 状态失败只影响对应主机，其他协议仍可展开、编辑和连接。
- 个性化开关重启后保持；关闭后旧主页可正常使用；不产生主机数据迁移。

### 10.3 操作和安全

- 分组视图左滑不会触发编辑或删除；显式编辑按钮能打开原协议编辑入口。
- RustDesk 连接按钮复用 Pad 模式按钮的视觉和触达尺寸，且只调用连接路由。
- 锁定主机、凭据缺失、未登录 Pro 账号等情况继续使用现有错误和权限语义。
- UI、日志、云同步和截图样例不出现密码、token、私钥或服务器公钥。

### 10.4 回归和证据

- 现有未分组主页、RDP、RustDesk、SSH/SFTP、VNC 的连接/编辑/删除流程无回归。
- 至少保存四种窗口状态的截图：全部收起、RustDesk 第一行展开、SSH 第二行
  展开、RustDesk ID 缺失/未知。
- 真实 API 23 Phone/Pad/PC 设备完成几何、焦点、旋转、页面复用和状态刷新验收；
  没有 HDC 或真实 RustDesk endpoint 时只能记录为 blocker，不能写成通过。
- 实施任何代码后，必须执行项目规定的 `default@OhosTestCompileArkTS` 和
  `assembleHap` 两项 Hvigor 门禁，并完成独立 review；本计划本身不替代这些门禁。

## 11. 灰度、回滚和风险

### 灰度

- 默认关闭分组视图，先在内部设备开启；保留用户级开关作为立即回退入口。
- 首轮只观察布局、状态刷新失败率、连接/编辑回归和状态误判反馈，不采集
  RustDesk ID、地址或凭据等敏感数据。

### 回滚

- 关闭分组开关即可回到旧主页，不能删除或重写任何主机记录。
- presence 接口不可用时只关闭状态 provider，保留 ID、分组和连接能力；不让
  一次状态服务故障阻塞主页。
- 发现布局回归时按阶段回退：先关闭 P3 状态，再关闭 P2 详情，最后关闭整个
  分组开关；每一步都保留未分组主页。

### 主要风险

- RustDesk peer presence 合同可能无法覆盖 OSS、Pro、直连和中继全部场景；需
  用 `unknown` 兜底，不可用 relay health 猜测。
- 不同协议当前数据 owner 不同，统一 UI 容易误把展示投影变成存储迁移；实施
  时必须保留 `sourceOwner` 和独立连接/编辑路由。
- Pad 与 PC 小屏的窗口宽度、密度和页面容器可能不同；220vp 是视觉基准，不应
  用固定像素把详情写死，必须做真实设备几何验收。
- 禁用左滑后，编辑入口的可发现性和无障碍焦点必须由显式按钮补齐。
- 状态刷新可能带来网络、耗电和限流压力；需要缓存、并发上限、取消和只刷新
  展开类型的策略。

## 12. 当前决策与待确认项

已按 Demo 采用的推荐决策：

- 分组开关默认关闭，保留旧列表。
- 固定四类、固定两列、四张卡等高；Pad/PC 小屏 220vp 基准高度。
- 同一时间只展开一个类型；详情固定在当前行下方并跨满内容宽度。
- 分组视图禁用左滑编辑；显式编辑按钮作为唯一编辑入口。
- RustDesk ID 显示在主机小卡片的主标识行；未知 presence 不显示为离线。

实施前必须确认：

- 当前 RustDesk OSS/Pro endpoint 是否具备可授权的 peer presence 能力，以及
  presence TTL、限流和错误码。
- RustDesk ID 是否需要复制按钮；若需要，按钮不能改变小卡片高度。
- 个性化开关是否只在本设备保存，还是纳入已有用户设置同步；默认不进入主机
  云同步，除非另有明确的数据合同。
- Pad/PC 小屏正式设计 token 的卡片高度、详情内卡片高度和最小可触达尺寸。
