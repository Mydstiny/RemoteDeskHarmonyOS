# 全协议键盘侧栏与沉浸式系统栏修复

## 目标

- RustDesk、RDP、VNC、Moonlight 的侧栏呼出按钮既能打开键盘入口，也能关闭当前虚拟键盘、组合键或功能键界面。
- 手机和平板侧栏始终处于可恢复的安全区域，极小窗口和 IME 压缩高度下仍有可点击关闭入口，内部列表可纵向滚到底。
- 侧栏自身及其卡片拦截所在区域的远端输入；其余远端画面继续可交互。
- RDP、RustDesk、VNC、Moonlight 和 SSH 在手机/平板连接期间统一隐藏顶部状态栏及底部导航/指示栏，并在离开连接时恢复。

## 根因与约束

- 键盘、组合键与系统 IME 分属不同 ArkUI 状态，旧侧栏只处理“打开”，自动折叠后没有统一关闭路径。
- IME 会压缩可用高度，RDP、Moonlight、VNC 的低高度策略会折叠侧栏并拒绝重新展开；关闭行为不能依赖完整侧栏重新出现。
- 横向收起手势与纵向 `Scroll` 并行，结束阶段若只判断 `offsetX/velocityX`，斜向纵向滚动会误收起甚至拖动 VNC 侧栏。
- 系统栏 API 在不同设备族上可能部分失败，三类系统栏必须独立 best-effort，不能因一个调用失败短路其余恢复。

## 实现

1. 把虚拟键盘、修饰键面板、组合键面板折叠为统一的 keyboard-surface 状态；同一侧栏入口在活跃时执行关闭。
2. 让 RustDesk、RDP、VNC、Moonlight 的折叠呼出柄优先关闭活跃键盘界面，保留极小高度下的可达性。
3. 统一限制侧栏滑动预览位移、可见高度、菜单锚点和滚动视口；纵向占优手势不得触发横向收起，VNC 也不得提交位置拖动。
4. 对 RDP、RustDesk、VNC、Moonlight、SSH 应用同一移动端沉浸策略；页面显示、前台恢复和方向变化时重申，退出时恢复。
5. SSH 对状态栏、导航栏和导航指示器分别执行 best-effort hide/restore，并保持系统栏属性更新独立可执行。
